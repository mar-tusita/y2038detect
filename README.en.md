# y2038detect

A static analysis tool that detects **Year 2038 problems** (32-bit integer overflow of Unix timestamps) in C source code.

By using AST (Abstract Syntax Tree) analysis via libclang, it can pinpoint issues more accurately than simple string search.

---

## What It Detects

| Type | Example |
|------|---------|
| Implicit narrowing conversion of `time_t` | `int t = time(NULL);` |
| Explicit cast of `time_t` | `int t = (int)now;` |
| Narrowing via function argument | Passing `time(NULL)` to `save(int t)` |
| Narrowing assignment to struct member | `s.ts = time(NULL);` (where `ts` is `int`) |
| Narrowing via function return value | `int get_ts(void) { return time(NULL); }` |
| `tm_year` upper bound set to year 2038 or earlier | `t->tm_year < 138` |
| Upper bound via `#define` macro constant | `#define LIM 138` … `t->tm_year < LIM` |
| Comparison of `time_t` with `0x7FFFFFFF` | `if (t < 0x7FFFFFFF)` (assumes 32-bit `time_t`) |
| Narrowing via `typedef` chain | `typedef time_t ts_t;` … `int x = ts_t_var;` |
| Narrowing via compound assignment | `int v; v += time(NULL);` |
| `time_t` argument to `printf`-family with mismatched format specifier | `printf("%d", time(NULL))` |
| Call to deprecated timestamp-setting API | `utime()`, `utimes()`, `lutimes()`, `futimes()` |

## Requirements

- **Python 3.10 or later** (3.12 recommended)
- **libclang Python bindings** (install with `pip install libclang`)
- A C compiler is **not required** (see below)

## Installation

### 1. Install Python

Python 3.10 or later is required (3.12 recommended). Install from [python.org](https://www.python.org/downloads/) or your OS package manager.

### 2. Install libclang

```bash
pip install libclang
```

This package bundles the Clang library — **no separate LLVM / Clang installation is needed**.

### 3. Get the Tool

Download the zip from the distribution site and extract it.

```text
https://mar-tusita.github.io/y2038detect/en/
```

Navigate to the extracted directory:

```bash
cd y2038detect-<version>
```

## Usage

### Basic

```bash
python y2038detect.py <file.c> [file.c ...]
```

Example:

```bash
python y2038detect.py src/timer.c
```

### Scan All C Files in a Directory

Specify a directory to recursively analyze all `.c` files under it:

```bash
python y2038detect.py src/
```

### Command-Line Options

| Option | Description |
|--------|-------------|
| `PATH` | C source file(s) or directory (multiple allowed) |
| `-I DIR` | Add include search path (multiple allowed) |
| `-D MACRO` | Define a preprocessor macro (e.g. `-DFOO` or `-DFOO=1`) (multiple allowed) |
| `-U MACRO` | Undefine a preprocessor macro (e.g. `-U_WIN32`) (multiple allowed) |
| `--target TRIPLE` | Target triple passed to libclang (e.g. `x86_64-pc-linux-gnu`) |
| `-X FLAG` | Pass FLAG directly to libclang (may be repeated). Use `=` to attach values starting with `-` (e.g. `-X=-ferror-limit=0`) |
| `--compile-commands FILE` | Path to `compile_commands.json` (see below) |
| `--exclude PATTERN` | Exclude files matching PATTERN from directory scans (multiple allowed, see below) |
| `--absolute` | Display file paths as absolute paths (default: CWD-relative) |
| `--color` | Force color output on (default: auto-detected — on when writing to a terminal, off when redirected or piped) |
| `--no-color` | Force color output off (setting the `NO_COLOR` environment variable has the same effect) |
| `--format FORMAT` | Output format: `default` (GCC-style) or `github` (GitHub Actions annotations). Auto-detected from the `GITHUB_ACTIONS` env var when omitted |
| `--json` | Output results as JSON |
| `--no-system-includes` | Skip compiler auto-detected system headers; use bundled stubs only |
| `--show-parse-errors` | Print libclang parse errors (including unresolvable `#include`s) to stderr (default: suppressed). Only prints; it does not change the analysis result |
| `--strict` | Disable all heuristic suppressions (see below) |
| `--version` | Print version and exit |

## Using compile_commands.json

Passing a `compile_commands.json` generated by CMake or [Bear](https://github.com/rizsotto/Bear) lets the tool automatically obtain per-file include paths and macro definitions. This is the most effective approach for real projects.

### CMake Projects

```bash
cmake -DCMAKE_EXPORT_COMPILE_COMMANDS=ON -B build
python y2038detect.py --compile-commands build/compile_commands.json src/
```

### With Bear (non-CMake)

```bash
bear -- make
python y2038detect.py --compile-commands compile_commands.json src/
```

The tool extracts `-I`, `-D`, `-std=`, and `-isystem` flags from each entry and applies them per file (both `command` shell string and `arguments` array formats are supported). Command-line `-I` flags always take precedence.

## Header File Resolution

The tool resolves include paths in the following priority order:

1. **User-specified `-I`** (highest priority)
2. **System headers** (auto-detected on Linux / macOS if gcc or clang is found)
3. **Bundled stubs** (`_stubs/` directory) — last resort

### Scanning FreeBSD Programs

The `_stubs_freebsd/` directory provides stubs for FreeBSD-specific headers. Add it with `-I` or configure it in `pyproject.toml`:

```bash
python y2038detect.py -I_stubs_freebsd/ src/
```

```toml
# pyproject.toml
[tool.y2038detect]
includes = ["_stubs_freebsd/"]
```

Included headers: `sys/event.h` (kqueue), `sys/queue.h` (LIST/TAILQ macros), `sys/tree.h`, `sys/sysctl.h`, `sys/proc.h`, `sys/user.h` (kinfo_proc), `sys/endian.h`, `sys/capsicum.h`, `sys/jail.h`, `sys/cpuset.h`, `sys/mac.h` (MAC framework), `ifaddrs.h`, `paths.h`, `pthread_np.h`, `net/if.h`, `net/if_dl.h`

### Scanning Linux Programs

The `_stubs_linux/` directory provides stubs for Linux-specific headers. Add it when scanning on non-Linux environments (Windows, macOS) or when `_stubs/` alone is insufficient.

```bash
python y2038detect.py -I_stubs_linux/ src/
```

```toml
# pyproject.toml
[tool.y2038detect]
includes = ["_stubs_linux/"]
```

Included headers: `sys/epoll.h`, `sys/eventfd.h`, `sys/inotify.h`, `sys/prctl.h`, `sys/sendfile.h`, `sys/signalfd.h`, `sys/sysinfo.h`, `sys/timerfd.h`

---

### Windows

On Windows, compiler auto-detection is **disabled** even if MinGW's gcc is present, to avoid compatibility issues with MinGW headers. Only bundled stubs are used. No extra configuration is needed.

```powershell
# Works with stubs only
python y2038detect.py src\timer.c
```

#### Using MinGW Headers

If your project requires MinGW-specific headers, specify the include path explicitly with `-I`:

```powershell
# Check MinGW include paths
gcc -x c -v -E NUL 2>&1 | Select-String "^ "

# Specify the path (MSYS2 example)
python y2038detect.py -IC:\msys64\mingw64\include src\timer.c
```

### Linux / macOS

If `gcc` or `clang` is installed, system include paths are **auto-detected** at startup. No extra configuration is needed.

```bash
python y2038detect.py src/timer.c
```

### Project-Specific Headers

For headers not in the system paths, add them with `-I`:

```bash
python y2038detect.py -I./include -I/opt/mylib/include src/timer.c
```

## Reading the Output

### Default Output

When issues are found, output follows a GCC / Clang style format:

```shell
src/timer.c:42:12: warning: implicit conversion of time_t to 'int' may truncate after 2038
    int saved = time(NULL);
               ^
src/timer.c:87:3: warning: tm_year compared with 138 (year 2038): upper bound excludes dates beyond 2038
    if (t->tm_year < 138)
    ^
```

File paths are shown relative to the current directory. Use `--absolute` to display absolute paths instead.

### Scan Summary

When scanning multiple files, a summary line is printed at the end:

```shell
# Issues found
python y2038detect.py src/
src/timer.c:42:12: warning: implicit conversion of time_t to 'int' may truncate after 2038
    int saved = time(NULL);
               ^
3 issues in 2 files (45 clean)

# No issues
python y2038detect.py src/
All 47 files clean.
```

The summary is not shown for single-file scans or in `--json` mode.

### JSON Output (`--json`)

Useful for integration with CI or other tools:

```bash
python y2038detect.py --json src/timer.c
```

```json
[
  {
    "file": "src/timer.c",
    "line": 42,
    "col": 12,
    "message": "implicit conversion of time_t to 'int' may truncate after 2038",
    "context": [
      { "line": 40, "text": "void update(void) {" },
      { "line": 41, "text": "    time_t now = time(NULL);" },
      { "line": 42, "text": "    int t = now;" },
      { "line": 43, "text": "}" }
    ]
  }
]
```

`context` is a few lines of source around the finding at scan time (6 lines before and 2 after
by default, shortened near the start/end of the file). It is `null` if the file could not be
read (e.g. it was removed after scanning).

### Exit Codes

| Code | Meaning |
|------|---------|
| `0` | No issues found |
| `1` | Issues detected, or libclang reported a fatal error and nothing was detected |
| `2` | At least one file could not be analyzed because of an internal error (an `internal error: PATH: ...` line is printed to stderr and the remaining files are still scanned; `2` takes precedence over `1`) |

### GitHub Actions Annotations

When running on GitHub Actions, the `GITHUB_ACTIONS=true` environment variable is set automatically. y2038detect detects this and switches to annotation format, which renders issues inline in the PR diff view:

```text
::warning file=src/timer.c,line=42,col=12::implicit conversion of time_t to 'int' may truncate after 2038
```

No extra configuration is needed. Use `--format=default` to force the standard terminal output, or `--json` to get JSON (which takes precedence over `--format`).

### Real-World Findings (Evaluation Results)

Examples of findings on real projects are available on the [evaluation results page](https://mar-tusita.github.io/y2038detect/evaluation/findings/).

## Excluding Files from Scans (`--exclude`)

Use `--exclude PATTERN` to skip files during directory scans. This is useful for excluding external code such as `vendor/` or `third_party/`.

```bash
# Exclude everything under vendor/
python y2038detect.py --exclude 'vendor/*' src/

# Multiple patterns
python y2038detect.py --exclude 'vendor/*' --exclude 'third_party/*' src/

# Exclude by filename suffix
python y2038detect.py --exclude '*.pb.c' src/
```

**Pattern rules:**

- Uses `fnmatch` glob syntax (`*` is a wildcard)
- A pattern like `vendor/*` also matches `src/vendor/foo.c` — the pattern is tested against trailing portions of the path, so no leading `*/` is needed
- Repeat `--exclude` for multiple patterns
- Files specified directly on the command line are never excluded (only directory expansion is filtered)

## Project Configuration (`pyproject.toml`)

You can set default values for options such as `--exclude` and `--compile-commands` in `pyproject.toml`, so you don't have to type them on the command line every time.

```toml
[tool.y2038detect]
compile_commands = "build/compile_commands.json"
exclude = ["vendor/*", "third_party/*"]
includes = ["include/"]
strict = true
extra_clang_args = ["-ferror-limit=0"]
```

| Key | Description | Equivalent CLI option |
|-----|-------------|-----------------------|
| `compile_commands` | Path to `compile_commands.json` | `--compile-commands` |
| `exclude` | List of exclude patterns | `--exclude` |
| `includes` | List of include paths | `-I` |
| `strict` | Set to `true` to disable all heuristic suppressions | `--strict` |
| `extra_clang_args` | List of flags passed directly to libclang | `-X` |

The tool searches for `pyproject.toml` starting from the current directory and moving up to parent directories, stopping at the first file found.

**Priority**: CLI arguments > `pyproject.toml` settings

`exclude` and `includes` are merged (values added on the command line are appended to those from the config file). `compile_commands` is overridden by the CLI if specified.

When a config file is loaded, the tool prints `note: using config from ...` to stderr.

> **Python 3.10 note**: Reading `pyproject.toml` requires Python 3.11 or later (the `tomllib` standard library module). On Python 3.10, the config file is silently ignored and only CLI arguments apply.

## Strict Mode (`--strict`)

By default, y2038detect applies several heuristics to reduce false positives, and some detection categories are off by default. Pass `--strict` to change all of these and scan more aggressively.

| Behaviour change | Normal behaviour | With `--strict` |
|------------------|-----------------|-----------------|
| LP64 `long` exception | On LP64 systems (Linux 64-bit, etc.), `long` is 8 bytes and not flagged | Always flagged regardless of size |
| Y2K-era `tm_year` hacks | Comparisons with values below 100 (e.g. `tm_year < 69`) are treated as Y2K two-digit-year handling and ignored | All values from 0 to 138 are flagged |
| Bounded variable tracking | Narrowing after `val %= 86400` is treated as a time-unit operation and ignored | Bounded-variable check is skipped; always flagged |
| Direct argument to `srand()` etc. | Narrowing passed to a seed-consuming function like `srand(time(NULL))` is ignored | Not suppressed; always flagged |
| `struct stat` timestamp field access | Not reported (off by default to avoid noise) | Accesses to `st_mtime`, `st_atime`, `st_ctime`, etc. are flagged (filesystem may store only 32-bit timestamps) |
| `utimensat()` / `futimens()` calls | Not reported (these are the recommended replacement APIs) | Flagged — still limited to 32-bit `time_t` on 32-bit systems |

```bash
python y2038detect.py --strict src/
```

You can also set it in `pyproject.toml`:

```toml
[tool.y2038detect]
strict = true
```

> **Note**: `--strict` increases false positives. Per-line `// y2038: ignore` suppression remains effective even in strict mode.

## Suppressing Warnings

### Per-line suppression

To suppress a warning for a known false positive or intentional exception, add a `y2038: ignore` annotation to the relevant line:

```c
// C++ style
int t = time(NULL);  // y2038: ignore

// C style
int t = time(NULL);  /* y2038: ignore */
```

The annotation is case-insensitive (`Y2038: IGNORE` also works).

### Range suppression

To suppress multiple consecutive lines at once, use `y2038: ignore-begin` / `y2038: ignore-end`:

```c
/* y2038: ignore-begin */
days  = (int)(val / 86400);
hours = (int)(val / 3600);
mins  = (int)(val / 60);
secs  = (int)(val % 60);
/* y2038: ignore-end */
```

If `ignore-end` is omitted, suppression continues to the end of the file.

### Automatic suppression after time-unit arithmetic

Narrowing conversions of a `time_t` variable are automatically suppressed when the variable has been reduced by a time-unit constant (60, 3600, 86400, 604800, or 7 for day-of-week arithmetic) using the modulo operator.

```c
time_t val = time(NULL);
val %= 86400;                    /* val is bounded to 0–86399 */
int hours = (int)(val / 3600);  /* no warning — fits in int */
int mins  = (int)(val / 60);    /* no warning */
```

The same applies when the modulo is part of a variable initializer:

```c
time_t seconds = t % 86400;        /* seconds is recognised as bounded */
int h = (int)(seconds / 3600);     /* no warning */
```

The divisor is recognised not only as an integer literal or `#define` macro, but also as a
`const time_t` local variable (including one initialized from an arithmetic expression that
references another such constant):

```c
const time_t secs_hour = 3600;
const time_t secs_day  = 3600 * 24;   /* arithmetic expressions are resolved too */
time_t seconds = t % secs_day;        /* seconds is recognised as bounded */
int h = (int)(seconds / secs_hour);   /* no warning */
```

The modulo itself is suppressed unconditionally whenever its divisor resolves to one of the
recognised time-unit constants, regardless of whether the left-hand operand is itself bounded
(e.g. day-of-week arithmetic like `(days+4) % 7`).

**Known limitation**: bounding achieved via accumulation across a loop (`for`/`while`), such as
repeatedly subtracting an array element or a function's return value, is not recognised. Use
`y2038: ignore` to suppress warnings manually in such cases.

## Integration with pre-commit

If your project uses [pre-commit](https://pre-commit.com/), you can run the check automatically on every commit.

### Setup

Add the following to `.pre-commit-config.yaml` at your project root:

```yaml
repos:
  - repo: https://github.com/mar-tusita/y2038detect
    rev: v0.9.4
    hooks:
      - id: y2038detect
```

Initial setup:

```bash
pip install pre-commit
pre-commit install
```

### Behavior

When you run `git commit`, only the staged `.c` files are analyzed automatically. If a Year 2038 problem is detected, the commit is aborted and a warning is displayed.

### Passing Options

To pass `--compile-commands` or `-I`, use `args:`:

```yaml
repos:
  - repo: https://github.com/mar-tusita/y2038detect
    rev: v0.9.4
    hooks:
      - id: y2038detect
        args: [--compile-commands, build/compile_commands.json]
```
